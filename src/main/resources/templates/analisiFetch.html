Analisi sperimentale: strategie di fetch

Caso d'uso: caricamento di tutte le squadre con i rispettivi giocatori. Confronto tra strategia LAZY (default) e strategia JOIN FETCH. Squadre caricate: 0.

LAZY (default)

Carica le relazioni solo quando vengono accedute. Genera il problema N+1 query: una query per le squadre, poi una aggiuntiva per ogni squadra quando si accede ai giocatori.

Conclusioni

La strategia LAZY genera il problema delle N+1 query: 1 query per caricare tutte le squadre, più una query aggiuntiva ogni volta che si accede alla lista giocatori di una squadra diversa (in totale N query in più).

La strategia JOIN FETCH risolve il problema eseguendo una sola query SQL che carica squadre e giocatori insieme.

Quando preferire LAZY: se la relazione (giocatori) non viene quasi mai consultata insieme all'elenco squadre, evitare il JOIN FETCH risparmia di trasferire dati inutili nella maggior parte delle richieste.

Nota: la cache di primo livello di Hibernate può influenzare i tempi misurati se la pagina viene ricaricata più volte nella stessa sessione.
